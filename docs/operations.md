# 运维、升级与故障排查

[文档导航](README.md) | [部署指南](deployment.md) | [后台管理](admin.md)

本文面向已部署站点的维护者。先确认当前环境、绑定和数据所在资源，再执行更新、迁移或清理；示例命令不会自动识别你的生产项目。

## 更新已有部署

1. 在 Cloudflare 项目中确认生产分支、当前部署提交、绑定与环境变量。`GET /api/config` 的 `metadataBackend` 表示实际分享元数据后端；同时绑定 KV 与 D1 时仍优先 KV。
2. 备份重要分享及配置，结束未完成上传。修改分片大小后旧会话可能不再兼容，应重新上传。
3. 较早的 D1 数据库先检查来源字段，按[来源迁移](upload-sources.md#已有-d1)补齐；新数据库使用完整 `schema/schema.sql`，不重复执行增量迁移。已有 D1 元数据还需在更新前执行[批次字段迁移](deployment.md#已有-d1-部署升级)。
4. 按原部署方式更新：Git 集成推送生产分支，CLI 重新构建发布，粘贴／拖放替换完整构建产物。
5. 保留资源绑定和 Secret，检查旧变量覆盖值。要使用当前默认值，删除旧覆盖或设 `MAX_FILE_SIZE=9900000000`、`PART_SIZE=100000000`。
6. 核对线上提交、资源版本与 `/api/config`，再按已授权范围验证上传、取件、后台和日志分类。

升级不会自动迁移 KV/D1 分享元数据，不会删除旧文件，也不会凭空补录历史来源或审计日志。新增防护默认包含上传与无效取件限流，规则见[安全防护](security.md)。

### 回退边界

回退代码前检查它是否能读取当前数据和执行当前规则：

| 变化 | 回退注意事项 |
|---|---|
| 多文件批次 | 旧版本无法识别批次清单及未发布状态。开始接纳批次后，回退目标也须支持批次格式 |
| D1 来源字段 | 增加的列和表可保留，不通过删数据回退 |
| KV 来源投影 | 更旧代码写回列表 metadata 可能丢失来源投影，原始分享 JSON 仍在 |
| 独立安全工作区 | 不支持该功能的旧代码不会执行新上传/取件和手动规则 |
| 上传/取件审计分类 | 更旧的严格解析器不认识新分类；先备份台账并准备兼容读取代码 |
| 原有环境变量 | 回退或重新部署不会自动清除控制台覆盖值 |

新审计继续沿用原存储键，无需升级迁移，但直接回退到不识别新分类的版本会影响日志查询与写入。不要为回退而清空分享、文件或整个数据库。

## 存储分工与备份

| 数据 | 优先存放位置 | 说明 |
|---|---|---|
| 分享、上传会话、访客备注、保留设置、周次设置 | `fileKV`，否则 `DB` | KV 和 D1 同时绑定时优先 KV |
| 文件正文 | `BUCKET`，否则 KV 的 `f:` 键 | 旧文件按存储键前缀读取 |
| 上传容量预留 | R2 的 `__file-relay/quota-v1.json` | 不可当普通缓存删除 |
| 访客周次数 | R2，否则 D1 `app_settings` 的 `__file-relay/guest-uploads-v1.json` | 包含带密钥摘要的周期计数 |
| 安全规则与计数 | R2，否则 D1 的 `__file-relay/security-v1.json` | 登录旧状态也继续读取 |
| 登录失败状态 | R2，否则 D1 的 `__file-relay/login-guard-v1.json` | 与独立安全规则共同参与判断 |
| 审计 | R2，否则 D1 的 `__file-relay/audit-v1.json` | 最近 30 天，最多 1,000 条 |

D1 的系统状态复用 `app_settings`，按需创建，不覆盖分享表。纯 KV 没有持久化审计与原子防护台账。

备份需同时考虑元数据、文件和系统状态；只有 D1 SQL 或 KV 分享记录不能恢复丢失的 R2 文件。恢复时保持存储键对应关系，并检查配额与实际对象是否一致。

D1 导出示例（替换数据库名，输出到仓库外受控目录）：

```bash
npx wrangler d1 export file-relay --remote --output=../file-relay-d1-backup.sql
```

KV 与 R2 使用 Cloudflare 控制台/API 或相应备份工具导出；项目没有一键完整备份或跨后端迁移命令。备份包含私有内容，应限制访问且不提交 Git。

### 切换存储后端

- KV 元数据 + KV 文件升级为 KV + R2：保留 `fileKV`，新文件改走 R2，历史 `f:` 文件仍由 KV 读取。
- 添加 D1 并同时保留 KV：分享元数据仍使用 KV，可由 D1 提供配额、防护和审计。
- 切换 KV 元数据到 D1：单独迁移分享、会话、备注和设置。若历史文件仍在 KV，还须处理文件正文和存储键；直接移除 KV 将无法读取这些文件，而保留同名 `fileKV` 又会继续选择 KV 元数据。
- 撤销 R2：旧对象不会随绑定移除而迁走，历史下载和遗留会话回收可能失败。先完成数据迁移与验证。

## 容量与免费额度

项目区分三类数值：

| 数值 | 含义 | 是否用于上传容量准入 |
|---|---|---|
| R2 已用 / 9.99 GB | 当前桶对象、系统对象及上传预留 | 是 |
| KV 用量 / 1 GB | 当前命名空间的日峰值，与账户共享免费额度对比 | 否 |
| Cloudflare 账单 | 账户资源的存储周期和操作用量 | 项目不查询完整账单 |

R2 通过条件写入先预留完整文件大小，再接收分片；已有文件对象、审计、防护及容量台账也占空间。正常完成保留对应预留，确认删除或取消后释放，避免并发低估。未完成分片可能持续占用空间，清理并非只删除界面记录。

默认单文件为 `MAX_FILE_SIZE=9900000000`。桶阈值在 `src/quota.ts` 的 `R2_CAPACITY_MAX` 固定为 `9990000000`，不是可从后台或环境变量修改的设置。修改该常量需要重新构建部署，并自行评估账户用量。

初始化成功的 `remainingBytes` 是预留本文件后的余量；容量拒绝返回本次申请可用的余量。数值为当时快照，并发操作和后续日志写入会继续改变占用，不能作为长期锁定的额度。

R2 Standard 免费存储为 10 GB-month/月，并有单独的 Class A/B 操作额度；9.99 GB 保护只覆盖当前桶，不能保证账户零费用。[R2 官方计费](https://developers.cloudflare.com/r2/pricing/)。KV 的值上限为 25 MiB，账户免费存储参考为 1 GB；取件计数会消耗写额度。[KV 官方限制](https://developers.cloudflare.com/kv/platform/limits/)。

本项目经 Worker 传输上传请求，将分片限制为最多 100 MB。Cloudflare 的入站请求体上限取决于域名套餐，不能用 R2 原生对象上限替代。[Workers 请求限制](https://developers.cloudflare.com/workers/platform/limits/#request-and-response-limits)。

## 自动清理

公开取件到期即停止；删除文件发生在“过期时间 + 保留天数”之后的下一次成功清理。默认保留 30 天，后台可设 0–3650 天，保存设置本身不删除数据。永久分享和仅次数耗尽的分享不会单独触发清理。已发布的批次按口令回收全部成员。未发布批次按创建时的 `SESSION_TTL_MS` 回收已传文件、未合并分片和容量预留。

| 触发方式 | 实际行为 |
|---|---|
| Workers Cron | 在控制台设置 `0 */6 * * *`，即每六小时执行 |
| Pages 首页访问 | 后台调用清理；KV 标记约六小时节流，不是严格分布式锁 |
| 外部定时器 | `POST /api/admin/cleanup`，使用管理员 Bearer 令牌 |

未绑定 KV 的 D1 模式没有该首页节流标记；Pages 没有访问时也不会凭时间到达执行首页清理。低流量站点可加外部定时器，步骤见[清理配置](deployment.md#清理配置)。

一次清理分批处理过期分享；遗留 R2 会话按 `SESSION_TTL_MS`（默认 24 小时）处理。失败的取消保留会话与预留以便重试。不能把超过保留期理解为精确到秒删除，也不能手工删除容量台账来“释放”尚未回收的字节。

## 页面更新与缓存

生产页面、样式和脚本来自同一份内联 Worker。构建为资源添加统一版本参数，静态响应带 ETag、`X-File-Relay-Build`、浏览器协商缓存及 CDN 禁止存储头。

刷新仍闪现旧布局或资源不一致时：

1. 检查 Pages 当前生产部署的提交，避免只确认“构建成功”却打开旧部署或预览域名。
2. 比较首页、CSS 和入口 JS 的 `X-File-Relay-Build`，应对应同一构建；资源参数不是历史资源托管服务。
3. 检查自定义域名 Cache Rules / Page Rules 是否覆盖缓存头，以及域名与 `pages.dev` 是否指向同一部署。
4. 核对提交是否更新了页面源码与必要构建产物；不要仅靠清浏览器缓存掩盖部署问题。

本地可运行 `test:first-paint` 与 `test:asset-version` 验证布局和版本机制，但它们不替代真实域名缓存检查。

## 常见问题

| 现象 | 优先检查 |
|---|---|
| 首页正常，API 提示未绑定元数据库 | 当前部署环境的 `fileKV` / `DB`；保存配置后是否重新部署 |
| 大文件走 KV 或只允许 25 MiB | R2 是否确实绑定为 `BUCKET`，`/api/config` 是否为 `r2` |
| 更新后仍是旧文件上限 | 控制台旧 `MAX_FILE_SIZE`、`PART_SIZE` 覆盖值 |
| 桶未到 9.99 GB 就拒绝 | 新文件申请、遗留上传预留、审计与系统对象都占空间 |
| KV 卡片无数字 | Analytics 三项配置、Token 权限/有效期、命名空间 ID 与采样日期 |
| 未备注访客无法上传 | 纯 KV 部署、周额度、永久/不限次选项、安全规则分别检查 |
| HTTP 403 / 429 / 503 | 查看 `error`、`reason`、`resetsAt` / `retryAt`；不要把所有拒绝都当作同一种封禁 |
| 后台日志为空 | 检查分类/日期、R2/D1 绑定及新版本上线时间；旧请求不会补录 |
| 已操作成功但日志未保存 | 检查审计存储，勿重复已完成的删除、清理或上传 |
| 同一 IP 被误封 | 现有会话在安全防护中解封；共享出口可能共同计数 |
| 忘记令牌 | 控制台修改 `ADMIN_TOKEN` 并应用配置；旧管理员与访客 Cookie 将失效 |
| 修改 Token 后来源变了 | 签名密钥变化使原 Cookie 失效，旧备注不会自动迁给新标识 |
| 有文件但下载失败 | 元数据、文件所在绑定、取件次数和有效期分别核对 |

管理员排障应使用请求状态、审计和 Worker 日志相互核对。IP 是网络出口，User-Agent 是自报信息，既不能证实真实身份，也不能可靠判断虚拟机或绕过代理后的地址。
