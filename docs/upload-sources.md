# 上传来源与管理员备注

[文档导航](README.md) | [后台管理](admin.md) | [API 参考](api.md#管理文件与来源)

上传来源帮助管理员关联浏览器记录与请求线索，不提供真实身份认证。列表显示访客标识或备注及大致属地；点击来源查看详情，点击文件名查看文件说明、预览和下载。

## 页面内容与备注

发送页“补充信息（选填）”默认展开：称呼最多 40 字符，文件说明最多 300 字符，同一批文件共用。自填信息仅管理员可见，不授予上传权限；文件说明在文件详情，自填称呼在来源弹窗。

来源弹窗直接展开访客、请求出口 IP、国家/地区/城市、ASN/网络组织、浏览器和记录时间。管理员备注与保存同行；备注最多 64 字符、单行，保存后替代同一访客新旧分享在列表中的标识，清空后恢复。

**非空备注同时授予上传豁免权限**：不限周文件次数，允许永久和不限次分享。全局文件大小、桶容量与安全规则仍生效。备注只能给确认过的来源；不能为了给陌生人做普通描述而误授权限。清空备注恢复新请求限制，不追溯修改旧分享，也不清空已有周计数。

“近期上传”自动加载同一签名访客最近 10 条现存分享，含文本；显示时间、大小、状态和该次上传的 IP/属地。近期文件名可打开文件详情，从文件进入来源时可返回原详情。

这份列表不含已删除分享、失败或未完成上传，不将取件次数算作上传者的下载行为。完整请求结果在[日志审计](admin.md#日志审计)中查看；KV 索引和备注权限传播可能短暂延迟。

## 识别范围

| 线索 | 来源与边界 |
|---|---|
| 访客标识 | 服务端签名 Cookie，HttpOnly、SameSite=Lax，HTTPS 下 Secure，有效期一年；关联浏览器数据，不绑定物理设备 |
| IP | Cloudflare 入口 `CF-Connecting-IP`，忽略客户端自填 IP 和转发头；反映当前网络出口 |
| 国家/地区/城市 | `request.cf`，缺失时显示已有信息或未知；可能为英文，不是精确定位 |
| ASN / 网络组织 | Cloudflare 网络属性，可辅助判断出口网络，不能据此断言恶意 |
| 浏览器/系统 | 由最多 256 字符的 User-Agent 推测，客户端可修改，不证明真实设备或虚拟机 |
| 称呼 | 上传者自填的线索，可冒用，不是权限凭证 |
| 管理员备注 | 管理员人工标记，同时影响上传权限，不是自动验证结果 |

代理后的真实 IP、精确位置、物理设备或好友关系均不由当前实现证明。不采集 WebRTC 地址，不主动探测代理内网，也不因使用代理或属地变化自动判断恶意。

切换代理但保留有效 Cookie 时可关联；清除浏览器数据、换浏览器、Cookie 过期或更换 `ADMIN_TOKEN` 后会形成新标识。不会仅凭相同 IP 自动合并访客。未设置管理令牌时不签发持久 Cookie，生产应设置 Secret。

R2 在初始化时固定上传来源快照，后续分片、完成或换网络不覆盖；KV 文件和文本在创建时记录。分片、完成、取消必须属于同一访客。审计另记录每次受审计请求的出口，因此后续请求位置可能与上传快照不同。

来源随分享删除，备注独立保存至清空，以便关联后续上传。旧记录缺来源显示“未记录”，不补造历史。

## 升级现有部署

### KV（默认）

直接部署兼容新字段的代码，不改旧分享；备注用独立 `v:` 键。完整来源保存在私有分享 JSON，列表 metadata 只保存访客、国家、地区、城市及时间投影，不包含完整 IP。

称呼、说明与网络字段扩展已有来源 JSON，不要求额外 D1 列。R2 初始化/文本接受 JSON 字段，KV 直传使用 URI 编码 JSON 的 `X-Upload-Context` 头；字段格式见[创建分享](api.md#创建分享)。

### 已有 D1

仅没有来源字段的旧数据库需要一次迁移。先在 SQL Console 检查：

```sql
PRAGMA table_info(shares);
PRAGMA table_info(upload_sessions);
SELECT name FROM sqlite_master WHERE type='table' AND name='visitor_notes';
```

确认 `shares.source_json`、`upload_sessions.source_json` 和 `visitor_notes` 是否已存在。新数据库直接执行完整 `schema/schema.sql`，不要再运行同名增量迁移。

旧库缺少这些字段时，在仓库根目录备份并迁移，数据库名替换为实际名称：

```bash
npx wrangler d1 export file-relay --remote --output=../file-relay-d1-before-source.sql
npx wrangler d1 execute file-relay --remote --file=./schema/migrations/0001-upload-source.sql
```

这是远端写操作。备份放在仓库外的受控位置；迁移只增加两个字段及备注表，不删除文件。执行中断时核对实际字段，仅补执行缺失语句，不盲目重跑全部 `ALTER TABLE`。已支持上传来源的 D1 部署无需再迁移；保留、周配额、防护与审计复用 `app_settings`。

回退时保留新字段，不删数据。很旧的 KV 代码可能在更新取件 metadata 时移除列表来源投影；原 JSON 不等于自动修复过的索引。[完整回退边界](operations.md#更新已有部署)。

## 管理接口

来源详情仅管理员可读，响应禁止缓存；公开取件不返回任何来源。列表是精简投影，完整 IP/浏览器由 `/api/admin/shares/:code/source` 提供，近期记录由其 `/activity` 子路径提供，备注使用 PUT。[完整输入输出](api.md#管理文件与来源)。

无来源的旧记录不能备注，返回 409；字段非法 400，无分享 404，未登录 401。`capturedAt` 为毫秒时间戳，界面按浏览器时区显示；地理和网络字段可以为 `null`。

## 回归与发布验收

开发者构建后选择 `npm run test:source`、`npm run test:upload-policy` 和 `npm run test:audit`。测试使用隔离的 KV、R2、D1 及签名访客夹具，覆盖迁移、公开响应隔离、备注权限、来源/文件弹窗、请求审计与手机主题。安装前提见[开发指南](development.md)。

生产验收应另行核对构建提交、资源版本、绑定与配置；本地模拟 IP/属地不能冒充线上真实访客识别实测。
