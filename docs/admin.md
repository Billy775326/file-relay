# 后台文件管理

登录后台后，点击内容栏的文件名打开详情弹窗。弹窗采用两列布局，显示完整文件名、格式、大小、文件与分享状态、上传者及属地、取件次数、创建时间、剩余有效期与清理安排，并提供下载按钮。点击上传者进入来源弹窗查看 IP 或编辑备注。MIME、可用的存储大小和入库时间放在“技术信息”折叠区。文本分享不显示文件详情入口。

管理员下载不增加取件次数；过期或次数用完的文件，只要仍在存储中就能下载。文件被删除后无法恢复。公开取件仍按原有有效期和次数限制执行。

文件状态在打开详情时检查：R2 只读取对象元数据，KV 获取流后立即取消，不将整个文件缓冲到内存。文件不存在时隐藏下载入口；存储服务异常或后端未绑定时显示“暂时无法确认”，仍可尝试下载。检查结果是当时状态，不保证文件在后续操作前不会被删除。

文件格式按扩展名归类，不代表内容校验；未提取软件版本、媒体时长或原文件修改时间。剩余有效期根据接口返回的服务器时间计算，是打开弹窗时的快照；“最早清理”不是精确删除时间。

## 登录防护

后台展开“登录防护”，可查看被封禁的 IP、失败次数、最近失败和自动解封时间，并手动解封。规则为 **同一 IP 在任意连续 10 分钟内登录失败 5 次，封禁新登录 30 分钟**。第 5 次失败即返回 429；封禁期间即使令牌正确也不能登录。成功登录会清除该 IP 未达到封禁阈值的失败记录。

- 绑定 R2 或 D1 后自动启用，无需新增 Secret。R2 优先，使用条件写入保证并发计数；仅 D1 时复用自动创建的 `app_settings` 表。所有部署方式使用相同规则。
- 纯 KV 部署保留原有登录，后台明确显示“未启用：需绑定 R2 或 D1”；KV 最终一致性不能可靠执行并发失败计数。
- 保护 `POST /api/admin/login` 和外部清理接口的 Bearer 令牌认证，两者共用计数，避免通过清理接口绕过令牌防猜测。封禁不影响上传、取件或静态页面；已有管理员会话仍可查看、解封和清理，不撤销会话。
- 来源 IP 只取 Cloudflare 入口的 `CF-Connecting-IP`，忽略用户提交的转发头；IPv6 归一化。没有可信 IP 的请求共用“未知来源”计数。共享出口可能相互影响，换出口不等于确认身份。
- 封禁到期自动失效；后续状态写入移除过期记录。状态最多保留 1,000 个有效 IP 项，不保存令牌或请求正文。容量已满且无法记录新的失败 IP 时返回 503，不覆盖其他有效记录；存储损坏或读写失败时拒绝新认证（503），不绕过防护。
- 全部管理员都被误封时，等待 30 分钟后重试；有未过期管理员会话时可直接解封。紧急恢复可在 Cloudflare 控制台备份后删除专用状态键 `__file-relay/login-guard-v1.json`（R2 对象，或 D1 `app_settings` 中同名键），这会清空全部登录失败与封禁记录，不能删除整个桶或数据库。

这是站点内的登录防护，不是运行 Fail2ban 守护进程，也不替代 Cloudflare 边缘的请求限流。请求仍会到达 Worker 并读取防护状态，分布式攻击仍可能消耗请求与存储操作额度。

## 未备注访客限制

在后台列表上方展开“未备注访客限制”，可修改每周文件数，默认 **5 次/周**。所有访客统一遵守全局单文件上限与存储后端限制：R2 默认 9.9 GB，KV 最多 25 MiB。旧设置中的 `maxFileSizeMB` 自动忽略，无需手动迁移。

- 每周文件数允许 0–1000；0 表示停止接受未备注访客的新文件上传。
- 每周按北京时间周一 00:00 重置。上传通过参数和权限检查并被配额系统接纳后计一次；取消、后续失败、容量不足或删除分享都不退回次数。分片重试和完成操作不重复计次。升级前的历史上传不回填计数。
- 同时限制签名访客标识和 Cloudflare 入口的请求来源 IP，任一额度耗尽即拒绝；清除 Cookie 或单独更换 IP 不会恢复另一维度的额度。同一出口的未备注访客共享网络额度，可能相互影响。
- 未备注访客不能创建永久有效或不限次取件的文件、文本分享；文本不计入文件周额度。
- 添加管理员备注可解除访客周次数限制，并允许永久、不限次分享；全局单文件上限与桶容量限制仍然生效。清空备注后恢复限制，原有计数不清零，已有分享不追溯修改。
- 设置与备注存放在 KV 时存在传播延迟；已开始的请求按读取到的规则执行。分片上传的后续请求会重新检查归属、大小和分享选项，权限收回后可能需要重新上传；取消仍允许原访客操作。

配额台账优先使用 R2 的条件写入；没有 R2 时使用 D1 条件更新。一次写入同时更新两种计数，并发冲突有限重试，读写失败则拒绝上传。每周使用带密钥的摘要代替台账中的原始 IP、访客标识；下一次新周期上传会替换上一周期的计数，台账最多 10,000 个计数项，超出后拒绝新接纳，不覆盖已有计数。

纯 KV 不能严格执行并发计数，因此不接受未备注访客的文件上传；绑定 `BUCKET` 或 `DB` 后启用。已备注访客仍可直传 KV 文件。无备注的访客可先提交限时、限次文本，供管理员在来源弹窗核对并备注。D1 计数复用自动创建的 `app_settings`，不修改已有分享表。

这项功能限制上传滥用，不验证现实身份，也不替代取件口令、登录接口的防爆破和边缘限流。换浏览器同时换出口仍可能绕过双维度配额；管理员备注应只授予确认过的来源。修改 `ADMIN_TOKEN` 会使已有访客 Cookie 失效，并改变配额摘要，不应将换令牌当作日常额度重置操作。

技术依据：[R2 条件写入](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)、[KV 并发写入限制](https://developers.cloudflare.com/kv/api/write-key-value-pairs/)。

## 过期保留天数

列表上方的“过期后保留”默认是 **30 天**，允许设置 **0–3650 的整数**。0 表示过期后即可清理；保存设置本身不会删除文件。

- 清理依据是“过期时间 + 保留天数”，不是上传时间。新设置适用于已有过期记录和后续过期记录。
- 文件和文本分享使用同一保留规则。永久分享不会自动清理；仅取件次数用完不会触发清理。
- 保留期结束后，在下一次成功的清理任务中删除元数据和文件。文件详情的“最早清理”不是精确删除时间。
- 保留期间文件仍占用存储，管理员可手动删除。未完成的上传会话仍按 `SESSION_TTL_MS` 清理，不受此设置影响。
- 已启动的清理使用启动时读取的设置；KV 后端的设置传播可能短暂延迟。

Workers 的 Cron、Pages 首页触发和外部定时调用共用此规则。Pages 无访问时不会仅因时间到达而执行首页清理；低访问量站点请按 [部署指南](deployment.md#清理配置) 设置外部定时器。

## 升级与存储

无需配置新的环境变量。KV 使用独立系统键保存天数，不修改现有分享结构。D1 使用 `app_settings` 表；旧数据库在首次保存设置时自动创建这张表，不覆盖分享和访客备注。没有保存过设置的旧数据库使用 30 天默认值。

设置读取失败或存储值损坏时，清理会停止，避免将错误配置当作 0 天删除文件。修复后等待下一次清理或使用已有管理员清理接口。

## 管理接口

以下接口都要求有效管理员 Cookie，返回 `Cache-Control: no-store`。

| 接口 | 输入与响应 |
|---|---|
| `GET /api/admin/login-protection` | 返回 `enabled`、`maxFailures`、`windowSeconds`、`banSeconds`、`bans`；封禁项含 IP、失败次数及 Unix 毫秒时间 |
| `POST /api/admin/login-protection/unblock` | JSON `{ "ip": "203.0.113.10" }`；需要管理员 Cookie、JSON 与同源请求，重复解封安全 |
| `GET /api/admin/upload-policy` | 返回 `{ "weeklyFileLimit": 5 }` |
| `PUT /api/admin/upload-policy` | 保存 `weeklyFileLimit` 整数字段；旧客户端传入的 `maxFileSizeMB` 忽略；需 JSON、管理员 Cookie，有 Origin 时必须同源 |
| `GET /api/admin/settings` | 返回 `{ "expiredRetentionDays": 30 }` |
| `PUT /api/admin/settings` | JSON `{ "expiredRetentionDays": 30 }`，返回保存后的同一字段；需要 `Content-Type: application/json`，如有 `Origin` 则必须同源 |
| `GET /api/admin/shares/:code` | 六位口令；返回文件详情，不增加取件次数 |
| `GET /api/admin/shares/:code/download` | 返回文件流及附件文件名；不增加取件次数 |

文件详情包含 `code`、`filename`、`size`（字节）、`mime`、`createdAt`、`expireAt`、`cleanupAfter`、`pickupCount`、`maxPickups`、`status` 和 `downloadUrl`，另含 `evaluatedAt`（检查时间）、`retentionDays`、`cleanupStatus`、`storage` 与 `source`。时间使用 Unix 毫秒；永久分享的 `expireAt`、`cleanupAfter` 为 `null`，不限次时 `maxPickups` 为 `null`。详情不包含完整 IP 或内部文件存储键。

- `cleanupStatus`：`permanent` 不自动清理、`active` 未过期、`retained` 过期保留中、`pending` 已达到清理时间。它与文件是否实际存在分别显示。
- `storage`：`state` 为 `available`、`missing` 或 `unknown`；R2 对象存在时附 `size`（字节）和 `uploadedAt`（入库时间），KV 或无法取得时相应值为 `null`。存储检查失败仍返回详情，不能将 `unknown` 当作删除。
- `source`：无来源的旧记录为 `null`，否则包含访客标识、国家、地区、城市、记录时间和管理员备注。完整 IP 仍仅由来源详情接口提供。

本次扩充不增加数据库字段，也不修改已有分享或取件计数。

未登录返回 401；非法口令、天数或非文件记录返回 400；记录不存在返回 404；下载时文件已清理返回 410。设置接口的非 JSON 请求返回 415，跨来源请求返回 403。降低保留天数可能使旧记录进入下一次清理范围。

`GET /api/config` 按当前访客返回 `maxFileSize`、`allowPermanent`、`allowUnlimited`、`weeklyFileLimit`、`uploadsRemaining`、`uploadsResetAt`（Unix 毫秒）和 `fileUploadAvailable`。已备注访客的周次数、剩余次数和重置时间为 `null`。不返回访客身份或 IP。

上传接口中，禁止的分享选项、会话归属错误或权限撤销返回 403；超过大小返回 413；周额度耗尽返回 429，附 `Retry-After` 和 `resetsAt`；配额存储不可用、损坏或繁忙返回 503。R2 初始化响应设置签名访客 Cookie，API 客户端必须在后续分片、完成、取消请求中保留该 Cookie。升级前创建的未备注分片会话需重新上传；遗留会话仍由清理任务回收。

## 验证

`npm run test:login-protection` 验证 R2/D1 并发失败封禁、到期与成功重置、管理员解封权限、存储故障、IPv6 以及移动端界面；仅使用隔离数据，不对生产站点尝试错误密码。

在仓库根目录安装依赖，构建后执行：

```bash
npm run build:pages
npm run test:retention
npm run test:admin-download
npm run test:upload-policy
```

需要 Python Playwright 与 Chromium。测试使用隔离的 KV、R2、D1 实例及测试文件，不连接生产数据。
