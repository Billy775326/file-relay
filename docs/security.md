# 安全防护

[文档导航](README.md) | [后台管理](admin.md) | [防护 API](api.md#安全防护)

后台顶部“安全防护”独立管理后台登录、上传、取件三个范围，不收纳在普通设置中。需要 `BUCKET`（R2）或 `DB`（D1）保存状态；纯 KV 显示未启用，无法保存持久规则。

这是站点内的类似 Fail2ban 功能，不运行外部守护进程，也不能替代 Cloudflare 边缘限流。已有管理员会话仍可管理规则，禁止新登录不会注销现有会话。

## 常用操作

| 目的 | 入口与操作 |
|---|---|
| 临时阻止某 IP | “封禁 IP” → “手动封禁”，选择范围、时长并填写原因 |
| 解除误封 | 选择对应记录 → 解封；可跨页选择并批量解封 |
| 调整自动阈值 | “防护规则”，按登录、上传、取件分别保存 |
| 限制国家/省州 | “地区封禁” → 添加地区；后台登录范围不可选 |
| 允许可信网络绕过自动限流 | “允许名单”，选择 IP 和适用范围 |
| 检查当前规则判断 | “规则测试”，填写模拟输入；不会真实封禁 |

默认不按使用代理、切换属地或浏览器类型认定恶意；共享代理/NAT 出口的不同访客可能共用网络计数。

## 手动封禁时长

IP 和地区规则统一为 **1 小时、1 天、7 天、永久**，没有自定义时间输入。新建 IP 默认 1 小时，新增地区默认永久；编辑地区默认“保持原到期时间”，不会因改原因或范围自动续期。

有限时长到期后失效。一个 IP 多个范围的封禁在列表合并显示，时间显示最后到期值，永久项优先；以各范围实际规则为准。自动限流的封禁时长是独立的分钟配置，不与手动四档混用。

## 默认自动防护

| 范围 | 计数事件 | 默认阈值 | 默认封禁 |
|---|---|---|---|
| 后台登录 | 管理令牌错误，包括清理接口的 Bearer 认证 | 连续 10 分钟内 5 次 | 30 分钟 |
| 上传 | 发起文件直传、文本或分片初始化，含后续参数校验失败；合法批次按文件数计 | 连续 10 分钟内 20 次 | 30 分钟 |
| 取件 | 查看分享/公开下载返回口令格式错误或不存在 | 连续 10 分钟内 10 次 | 30 分钟 |

达到阈值的那次请求被拒绝。登录成功清除未触发封禁的失败记录；取件成功、已过期、次数用完不增加无效口令计数。分片与完成请求仍检查范围/地区规则，但不重复计上传频率；拥有会话的访客仍可取消以释放可回收预留。

可分别停用规则，或设置阈值 1–10,000 次、窗口 1–1,440 分钟、封禁 1–10,080 分钟。保存规则清空上传/取件未触发计数，保留已生效封禁和旧登录状态；停用规则不会自行解除已有封禁。

这与每周文件额度分开：管理员备注解除周额度和分享选项限制，不豁免网络防护。默认上传频率按发起请求计数，不只统计成功文件。

## 名单与优先级

| 类型 | 生效范围 | 关键约束 |
|---|---|---|
| 手动 IP 封禁 | 登录、上传、取件 | 单个 IPv4/IPv6，指定范围和原因 |
| 自动 IP 封禁 | 触发对应范围 | 使用该范围的阈值和时长 |
| 允许名单 | 指定范围的自动限流 | 不绕过手动封禁、地区、登录认证、周额度或分享规则 |
| 地区封禁 | 上传、取件 | 禁止作用于后台登录 |

地区填写两位国家代码和可选省州代码，例如 `CN / ZJ` 或 `US / TX`；省州留空匹配整个国家。界面提供建议，也接受符合格式的代码。实际匹配使用 Cloudflare 的 `request.cf.country` 和 `request.cf.regionCode`，未知属地不匹配具体地区，不信任客户端自填定位。[Cloudflare 请求属性](https://developers.cloudflare.com/workers/runtime-apis/request/#incomingrequestcfproperties)。

来源 IP 取 Cloudflare 入口，忽略用户提交的转发头并归一化 IPv6。无可信 IP 时共用未知来源计数；网络出口不证明真实设备或代理后的身份。

“规则测试”只根据当前配置和管理员填写的模拟 IP、地区、次数判断，不查询真实定位，不写计数或名单。放行只说明通过防护，不保证口令、文件或登录认证本身成功。

## 筛选、导出与审计

先选择封禁/允许/地区列表，再按关键词、范围和封禁类型筛选。导出 CSV 包含当前类别的全部匹配记录；未应用的筛选改动需先提交。批量解封在选中记录后出现。页面可手动刷新；安全页可见、没有弹窗或待应用筛选时每分钟刷新。

规则/名单变更、新自动封禁进入审计。上传/取件被 IP、地区或限流拦截也记录，重复拦截按固定五分钟窗口合并次数，详情保留首次与最近时间。登录封禁后的重复重试不逐条记录，到期失效不是独立事件。[日志覆盖与保留](admin.md#日志审计)。

## 存储与升级

规则与上传/取件计数保存在 `__file-relay/security-v1.json`，优先 R2，未绑 R2 时使用 D1 `app_settings`；旧登录状态继续读取 `__file-relay/login-guard-v1.json`。条件写入有限重试，配置版本冲突返回 409，需刷新后重新审核；存储不可用时拒绝受保护请求，不绕过规则。

最多保留 200 条允许名单、200 条地区规则、1,000 条活动封禁、1,000 个 IP/范围计数组合和 20,000 个窗口时间点。过期封禁及窗口计数在后续状态处理中清理，地区规则保留以供编辑。记录满且无法安全新增时返回 503，不覆盖其他有效项。

已有来源字段的部署无需分享表迁移，也不重置旧封禁；更早的 D1 升级见[迁移步骤](upload-sources.md#已有-d1)。回退旧代码可能不再执行新规则，边界见[运维说明](operations.md#更新已有部署)。

请求仍到达 Worker 并消耗读取、计数与审计操作；重复拦截合并不免除存储写入。大量并发可能因竞争返回 503，不能保证免费额度不被耗尽。

## 被拦截时的体验

上传/取件提示会保留当前内容。临时限制根据服务端时间显示剩余等待时间，倒计时结束后由用户重试；没有到期值时不显示倒计时。分片遇到安全错误停止自动重试并尝试取消会话，恢复同一批次时跳过已上传文件，并继续使用原接纳记录。

“联系站长”打开邮件草稿，不自动发送；也可复制邮箱与反馈信息。反馈只包含操作、公开限制类型、时间和请求编号，不放入口令、文件名或 IP。`requestId` 可与 Worker 日志的 `security_rejection` 关联，实际可查范围取决于部署日志设置和保留期。

公开错误可返回 `reason`、`retryAt`、`Retry-After` 和服务端时间；浏览器直接访问下载链接时可得到同状态 HTML 提示，API 得到 JSON。Cloudflare 在 Worker 前返回的拦截不保证采用本项目格式。[错误字段](api.md#常见错误与重试)。

## 误封与恢复

有现存管理员会话时，在“安全防护”解封，核对适用范围与允许名单。所有新登录都被自动误封且没有可用会话时，可等待所配置时长；手动永久规则需要通过受控配置恢复，不能等待解决。

紧急处理旧登录状态前先备份 `__file-relay/login-guard-v1.json`，明确它不包含新工作区的全部手动规则。删除这一专用旧状态键不会清空 `security-v1.json` 中的规则，也不应删除整个桶/数据库；清空状态会丢失原失败与自动封禁记录。

## 接口与验证

使用 [防护 API](api.md#安全防护) 读取配置版本、写入名单或只读测试；旧 `/login-protection` 接口保留兼容，新的界面统一使用安全工作区。UI 四档之外的整数分钟范围仅为既有 API 兼容，不表示界面提供自定义时长。

构建后运行 `npm run test:security` 和 `npm run test:login-protection`，使用隔离 R2/D1/KV 与浏览器验证范围、地区、权限、并发、失效和故障拒绝。不要用生产错误密码尝试替代隔离测试。[开发环境](development.md)。
