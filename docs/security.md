# 安全防护

后台顶部的“安全防护”用于管理登录、上传和取件的访问规则。需要绑定 `BUCKET`（R2）或 `DB`（D1）；纯 KV 部署显示未启用，不能保存规则。已有管理员会话仍可管理规则，封禁后台登录不会注销现有会话。

## 手动封禁时长

手动 IP 封禁和地区封禁均可选择 5／15／30 分钟、1／6／12 小时、1／3／7／30 天、永久，或选择“自定义”后输入整数并指定分钟、小时或天；自定义范围为 1 分钟至 30 天。手动 IP 封禁默认 30 分钟，新增地区规则默认永久；保存后按所选时长计算到期时间，到期自动失效。

编辑地区规则默认“保持原到期时间”，不会因修改原因或范围而延长封禁。自动防护规则仍使用原有独立的分钟设置。

## 默认自动防护

| 范围 | 计数事件 | 默认阈值 | 封禁时长 |
|---|---|---|---|
| 后台登录 | 管理令牌校验失败，包括清理接口的 Bearer 校验 | 10 分钟内 5 次 | 30 分钟 |
| 上传 | 发起文件直传、文本分享或分片初始化请求，包含后续参数校验失败的请求 | 10 分钟内 20 次 | 30 分钟 |
| 取件 | 取件或公开下载接口返回口令格式错误、不存在 | 10 分钟内 10 次 | 30 分钟 |

达到阈值的那次请求即被拒绝。计数按 IP 与保护范围分别处理；分片、完成请求仍检查封禁和地区规则，但不重复计次。已拥有的上传会话允许取消，方便释放预留空间。成功取件、已过期或次数用完不作为错误口令计数。

“防护规则”中可修改阈值 1–10,000 次、窗口 1–1,440 分钟、封禁 1–10,080 分钟，或分别停用规则。保存会清空上传和取件的未触发计数；已有封禁和旧登录失败记录保留。暂停规则不解除已有封禁。

这与未备注访客的周额度是两套限制：管理员备注只解除周额度和分享选项限制，不豁免这里的网络防护。同一代理出口的不同访客共享 IP 计数。

## 名单与优先级

- **封禁 IP**：支持单个 IPv4/IPv6、保护范围、原因及有效期；可跨页选择并批量解封。一个 IP 在多个范围封禁时列表合并显示，自动解封时间是最后一个范围的到期时间；永久项优先。
- **地区封禁**：填写国家代码和可选省州代码，例如 `CN / ZJ`、`US / TX`。常用值可从建议中选择，也可手动输入其他代码。省州留空表示整个国家。后台登录不可选择，服务端也拒绝该范围。
- **允许名单**：只豁免所选范围的自动封禁，不绕过手动 IP 封禁、地区封禁、登录认证、取件次数或上传配额。

地区来自 Cloudflare 的 `request.cf.country`、`request.cf.regionCode`；不信任用户自行提交的属地头，也不主动探测代理后的地址。未知属地不匹配具体地区，其他规则仍参与判断。参见 [Cloudflare 请求属性](https://developers.cloudflare.com/workers/runtime-apis/request/#incomingrequestcfproperties)。

“规则测试”由服务端根据当前配置计算，但使用管理员手动提供的 IP、地区和次数，不查询真实定位，不写入计数或封禁。返回放行仅表示通过防护，不保证登录或取件本身成功。

## 筛选、导出与审计

先选择名单类别，再填写关键词、保护范围及封禁方式，点击“筛选”。输入变更尚未应用时禁止导出。CSV 包含当前类别的全部匹配记录，不仅是当前分页；数据以最近一次读取的状态为准。

规则变更和新的自动封禁进入日志审计，不记录令牌、文件正文或请求正文。重复被封禁的请求不会每次都写日志。列表可手动刷新，并在安全页可见、没有弹窗或待应用筛选时每分钟刷新。

## 存储与升级

规则和上传/取件计数存放在 `__file-relay/security-v1.json`，优先 R2，未绑定 R2 时使用 D1 的 `app_settings` 表。条件写入有有限重试，配置版本冲突返回 409，要求刷新后重新编辑；存储不可读、损坏或容量已满返回 503，受保护的请求不会绕过防护。

最多保留 200 条允许名单、200 条地区规则、1,000 条活动封禁、1,000 个 IP/范围计数组合和 20,000 个窗口内时间点。过期自动记录在后续读取/写入时清理；地区规则保留状态供管理员编辑或删除。纯 KV 不承诺可靠并发防护。

升级不迁移、删除分享数据，也不重置原有登录封禁；继续读取 `__file-relay/login-guard-v1.json`。新表复用已有 `app_settings`，无需修改分享表。回退旧代码会忽略新的安全规则，但保留这些状态；旧代码只执行原有登录防护，应明确接受这一差异后再回退。

防护运行在 Worker 内，仍消耗请求与存储读写额度，不能替代 Cloudflare 边缘限流，也不能保证免费额度不被耗尽。大量并发写入同一状态对象时，竞争可能返回 503。

## 接口与验证

上传与取件被拦截后保留当前文件、文本及口令，并显示持续提示。临时限制按服务端时间显示剩余等待时间，倒计时结束后由用户手动重试；手动封禁或地区限制没有到期时间时不显示倒计时。重试仍会重新校验规则，不保证到期后一定放行。分片请求遇到 `security_blocked` 或 `security_unavailable` 时立即停止自动重试，并尝试取消已创建的会话。

提示中的“联系站长”通过 `mailto:iblykk@gmail.com` 打开邮件草稿，也可复制邮箱和反馈信息。草稿仅包含操作、公开限制类型、时间和请求编号，不自动发送，不包含口令、文件名或 IP。请求编号可在 Worker 日志的 `security_rejection` 中关联，是否可查询取决于部署的日志启用及保留设置；不会为每次重复拦截新增持久审计记录。

公开安全错误保留原有 HTTP 状态码与 `error`、`message`，增加 `reason`（`rate_limit`、`access_rule`、`region`、`service_unavailable`）、`requestId`、`serverTime`，有期限时包含 `retryAt`（Unix 毫秒）和 `Retry-After`（秒）。浏览器访问下载链接且接受 HTML 时返回同状态的提示页面，API 请求仍返回 JSON；下载成功继续使用服务端的附件响应。这些提示只覆盖站点自身防护，不覆盖 Cloudflare 在 Worker 前返回的拦截页面。

下列后台安全接口需要管理员 Cookie，写操作要求同源和 JSON。

| 接口 | 行为 |
|---|---|
| `GET /api/admin/security` | 返回是否可用、配置版本、三类规则和当前名单；不返回未触发计数 |
| `POST /api/admin/security` | `{ action, configRevision, ...参数 }`；操作为 `rules`、`ban`、`unban`、`allow`、`removeAllow`、`region`、`removeRegion` |
| `POST /api/admin/security/test` | `{ ip, scope, country, region, count }`；只读计算返回 `{ blocked, reason }` |

`ban` 使用 `{ ip, scopes, note, minutes }`（整数 1–43200 分钟，0 为永久）；`allow` 使用 `{ ip, scopes, note }`；`unban` 使用 `{ ips }`；`region` 使用可选 `id` 与 `rule: { country, region, scopes, enabled, reason, until }`，`until` 为 Unix 毫秒或 `null`。修改规则传完整的 `rules` 对象，各范围包含 `enabled`、`limit`、`window`、`duration`。

旧 `/login-protection` 接口保留兼容，用于读取/解除原有登录封禁。新界面统一使用安全工作区。

在仓库根目录构建后运行 `npm run test:security` 和 `npm run test:login-protection`。测试使用隔离的 R2、D1、KV 与浏览器，不连接生产数据。
